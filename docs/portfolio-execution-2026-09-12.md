## Deployment order after concrete approval

1. Merge and push the shared harness branch with a merge commit, preserving the commit pinned by CI. The pin must be remotely reachable before relying on it in another PR. Leave the 18 older compatible workflows alone; their broader usage rollout is a separate scope.
2. Install the reviewed shared runner version in its existing managed environment. Check `backlog-run rework --help` and `backlog-run approve --help` for `--reviewed-sha` before activating Romance's new caller. Retain the old environment for rollback. Do not change an active runner underneath a task.
3. Merge and push the Romance continuation branch. Its main-checkout poller will then use the new rework/approval arguments. Existing old review records can supply their displayed exact SHA. Branch changes still require the current work to be reviewed.
4. Merge and push the VPS delivery branch. Install the reviewed `tg-send` first. Before replacing `agents`, compare the installed file to the recorded old SHA `6a91916f13f262389ef36b369b6dc06a6fe907df282e302a695eea2684430212`, retain a backup, and replace only that command with the reviewed bytes. The normal installer refuses a mismatching destination; do not bypass that refusal by overwriting an unexplained version. `python3 install.py --check --bin-dir "$HOME/.local/bin"` verifies the final installed set.
5. Check bridge state for pending/uncertain owner actions, stop/restart the existing bridge once using the reviewed source, and verify its process and journal. Old pending flags are intentionally not reusable approvals. The watchdog's existing main-checkout wrapper follows the approved shared merge; retain its state files and inspect provider receipts on the next normal cycle. A merge may therefore change watchdog behavior before a later service restart.
6. Merge and push the Attain feedback branch, then let the existing trusted market controller perform its normal reconciliation. Workers keep no-live-write rules. Install the updated Notion queue into its separate versioned runtime following [its runbook](../workqueue/README.md); merging the shared source does not update that installed environment. Do not rerun provisioning.
7. Activate the private cockpit using [its placement and resource proposal](../cockpit/README.md). Verify authenticated reads first. The Hold action was browser-tested on a disposable queue; a live owner-selected item is the remaining activation check. No public host, new tunnel or generic action endpoint is required by this package.

The feedback and watchdog controllers read main directly. Their approved merges are also operational changes at the next scheduled run. Prepare the runner dependency first, and do not describe these merges as documentation-only.

The merge recommendations approve only the named source merges and pushes. They do not install the shared runner, replace `agents`, restart the bridge, or activate the cockpit. If Romance source is merged before the runner is installed, its capability check leaves the owner's request pending and explains the missing runtime update before consuming a session slot. Treat that as an incomplete rollout, not a working rework loop.

The original shared checkout has identical untracked copies of the audit documents, and Attain has identical untracked `AGENTS.md` and `IDEAL_STATE.md` copies. At merge time, compare their bytes again and temporarily preserve only the identical colliding copies before merging. Keep any differing file and all unrelated working changes. In particular, Romance's active engagement records and Attain's other untracked documents are outside this package.
